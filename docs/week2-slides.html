Is that difference real — or could it be chance?

External validity

Suppose we do establish that the gap in our data is real, not chance. What exactly are we then entitled to say?

Only that it’s real for this class, on this day, using this task — not, without more work, anything about phone and laptop users in general.

That gap between what our data shows and what we’d like to claim is called external validity: whether the pattern in our data is the same as the general pattern we actually care about.

Question: what do you think external validity means for our own reaction-time gap, specifically?

Three threats to external validity

Assessing whether our data represents the same general pattern we actually care about.

  • Time — we have data from the past (or this one session); we care about the future
  • Space — our data is one class, in one room, on one day; would the pattern hold elsewhere?
  • Sub-groups — our data is this cohort; would it hold for a different group of people?

Source: Békés & Kézdi (2021), Data Analysis for Business, Economics, and Policy, Ch. 5

The sampling distribution

One sample among many

Our Week 1 data is one dataset — one of many that could have been collected. If we ran the exercise again tomorrow, we’d get different numbers, purely by chance.

  • Many possible datasets = repeated samples from the same underlying data generating process
  • A statistic computed from data (like the mean) therefore has its own distribution — its value differs from sample to sample.
    • Today’s mean will differ from tomorrows.
  • That distribution is called the statistic’s sampling distribution, and it is a different object from the distribution of the variable itself

Source: Békés & Kézdi (2021), Ch. 5

Here we have the distribution of all students average reaction time captured last week.

The red curve is a Normal(μ, σ) fitted to it. This is our assumed data-generating process (DGP).

Using these parameters, we can use Python to pretend that we’ve run last week’s test many times, creating a new dataset each time drawing from the same distribution.

Bessel’s correction

Bessel’s correction: back in Week 1 we used n − 1, not n, to compute a standard deviation — here’s why. An unbiased estimate of the population variance divides squared deviations by n − 1, not n — the sample mean already fits this exact sample as closely as possible, so squared deviations from it slightly understate the true spread. Dividing by n − 1 corrects for using one number’s worth of information, since the sample mean was calculated from these same values.

Békés & Kézdi’s own formulas divide by n throughout — harmless at the scale of their case studies, where the difference is vanishingly small. This module generally divides by n − 1 instead, since a class of students is small enough that the difference is real. Ultimately, it is not a big deal but is important to know.

Law of Large Numbers: as the number of independent draws increases, the sample mean converges to the true mean. An estimator whose expected value equals the true parameter is called unbiased.

2. Asymptotic normality

The sampling distribution of the mean approaches normal as sample size grows — regardless of the shape of the population.

{
  const panels = [
    { label: "n = 5",  vals: clt_n5  },
    { label: "n = 15", vals: clt_n15 },
    { label: "n = 30", vals: clt_n30 },
  ]

  const all  = [...clt_n5, ...clt_n15, ...clt_n30]
  const xmin = Math.floor((d3.min(all) - 5) / 10) * 10
  const xmax = Math.ceil( (d3.max(all) + 5) / 10) * 10
  const bw   = 8

  // Normal curve overlay
  function normalCurve(vals, n, bw) {
    const mu  = d3.mean(vals)
    const sig = d3.deviation(vals)
    return d3.range(xmin, xmax, 2).map(x => ({
      x,
      y: (vals.length * bw) * (1 / (sig * Math.sqrt(2 * Math.PI))) *
         Math.exp(-0.5 * ((x - mu) / sig) ** 2),
      label: `n = ${n}`
    }))
  }

  return Plot.plot({
    height: 480,
    marginLeft: 60,
    marginBottom: 36,
    fx: { label: null, padding: 0.1, domain: panels.map(p => p.label) },
    x:  { label: "Sample mean (ms)", domain: [xmin, xmax] },
    y:  { label: "Count" },
    marks: panels.flatMap(({ label, vals }) => [
      Plot.rectY(vals.map(v => ({ x: v, fx: label })),
        Plot.binX({ y: "count" },
          { x: "x", thresholds: d3.range(xmin, xmax + bw, bw),
            fill: "#2d6a4f", fillOpacity: 0.6, fx: "fx" })),
      Plot.line(normalCurve(vals, label, bw),
        { x: "x", y: "y", fx: () => label,
          stroke: "#e63946", strokeWidth: 2 }),
      Plot.ruleX([d3.mean(vals)], { fx: () => label, stroke: "#1a1a2e", strokeWidth: 1.5, strokeDasharray: "3,3" }),
    ])
  })
}

Central Limit Theorem: for large enough n, the sampling distribution of the mean is approximately Normal(μ, σ²/n), regardless of the population’s shape. This is why the normal distribution is everywhere.

SE = σ / √n. To halve the standard error, you need to quadruple the sample size. Precision is expensive.

Estimating uncertainty from real data

But we don’t actually know the DGP

Everything so far assumed a known population — Normal(μ, σ) — so we could watch 1,000 simulated samples land around the true value.

In reality, we have one dataset: the reaction-time data collected last week. No known μ, no known σ, no ability to simulate 1,000 more classes.

Two ways forward: a formula, or a computational trick called the bootstrap.

The standard error formula

\[SE(\bar{x}) = \frac{1}{\sqrt{n}} \, SD[x]\]

  • Larger when the data is more spread out (SD[x] larger)
  • Smaller when the sample is bigger (n larger)

Source: Békés & Kézdi (2021), Ch. 5

The bootstrap idea

  • Take the original dataset and draw repeated samples from it, with replacement
  • Each draw can be picked more than once; some observations won’t be picked at all
  • Compute the statistic (e.g. the mean) on each resample
  • The spread of those resampled statistics approximates the sampling distribution — without ever needing to know the true DGP

Source: Békés & Kézdi (2021), Ch. 5

Bootstrap samples

Three resamples drawn with replacement from the same original sample of 6 — notice item 4 appears three times in Sample 3, while items 3 and 5 never get drawn there at all. The spread across the resulting statistics is the bootstrap’s estimate of the sampling distribution.

Source: Békés & Kézdi (2021), Ch. 5 — recreated schematically (after Fig. 5.4, “Bootstrap samples”)

What is a confidence interval?

A confidence interval (CI) is a range where we expect the true value — in the population, or general pattern, that our data represents — to fall, with a probability we choose. Analysts typically pick 95%, sometimes 90% or 99%.

From the perspective of a single sample: there is a 95% chance that the true value lies within this interval — and a 5% chance it doesn’t. We don’t know - we can’t know - which case we’re in.

Source: Békés & Kézdi (2021), Ch. 5

Building the interval

A CI is a symmetric range around the estimated value, built from the SE:

\[CI = \text{statistic} \; \pm \; (\text{critical value} \times SE)\]

Confidence level Critical value
90% 1.6 × SE
95% 2 × SE
99% 2.6 × SE

Wider interval → more confident it contains the truth, but less precise about where. There’s no free lunch: more confidence costs precision.

Note

For a 95% confidence level, the precise critical value is 1.96 — but 2 is a decent rule of thumb.

Confidence intervals

Quick recap

  • We want to generalise from our data — statistical inference
  • Two ways to estimate the uncertainty in a statistic: a formula (\(SE = SD/\sqrt{n}\)) or the bootstrap (resample with replacement, look at the spread)
  • Under the conditions the formula needs, the two agree — but the bootstrap keeps working even when no formula exists
  • A 95% CI is the estimate ± 2 × SE — a range we expect to contain the true value, and 95% of intervals built this way actually do
  • Using the CI, we can now make a statement about the population, or general pattern, that our data represents

Testing a hypothesis

Fisher’s tea test

A woman claims she can tell, by taste, whether the milk or the tea was poured into the cup first.

Ronald Fisher didn’t just take her word for it — and he didn’t dismiss her either. He designed a test: several cups, milk-first and tea-first in random order, unknown to her. She has to identify all of them correctly.

If she’s just guessing, we can calculate exactly how likely she is to get them all right by chance. If she does far better than chance predicts, that’s evidence for her claim.

This is the entire logic of hypothesis testing, built from one experiment in 1920s Cambridge.

The null is protected

Testing a hypothesis means asking: is there enough evidence in the data to reject a default, protected assumption?

Criminal court

  • Assume innocence
  • Only convict if evidence is strong
  • “Not guilty” ≠ proven innocent — just not enough evidence

Hypothesis testing

  • \(H_0\) (null): protected, assumed true until shown otherwise
  • \(H_A\) (alternative): what we suspect instead
  • Failing to reject \(H_0\) ≠ proving it true — just not enough evidence

Source: Békés & Kézdi (2021), Ch. 6

Task — state our hypothesis

Write \(H_0\) and \(H_A\), in words and in symbols, for our own question: does device (phone vs. laptop) affect reaction time?

\[H_0: \; \bar{x}_{\text{phone,true}} - \bar{x}_{\text{laptop,true}} = 0\] \[H_A: \; \bar{x}_{\text{phone,true}} - \bar{x}_{\text{laptop,true}} \neq 0\]

No true difference in reaction time by device, versus: there is one.

The t-test

The t-statistic

The test statistic measures how far our estimate is from what \(H_0\) predicts, in units of standard error.

\[t = \frac{\hat{s}}{SE(\hat{s})}\]

For a difference between two averages, \(\bar{x}_A\) and \(\bar{x}_B\):

\[t = \frac{\bar{x}_A - \bar{x}_B}{SE(\bar{x}_A - \bar{x}_B)} \qquad SE(\bar{x}_A - \bar{x}_B) = \sqrt{\frac{SD_A^2}{n_A} + \frac{SD_B^2}{n_B}}\]

Note

This needs the sampling distribution of \(\bar{x}_A - \bar{x}_B\) to be approximately normal — not reaction time itself, which we already know is right-skewed. With dozens of trials in each group, the CLT (see “2. Asymptotic normality” earlier) makes that a safe bet regardless of the raw variable’s shape.

Source: Békés & Kézdi (2021), Ch. 6

Two ways to be wrong

\(H_0\) is true \(H_0\) is false
Don’t reject True negative False negative (Type II error)
Reject False positive (Type I error) True positive

The test is designed to make false positives rare — the null is protected, so we deliberately make Type I errors less likely than Type II.

The p-value

The p-value is the smallest level of significance at which we could still reject \(H_0\) — the probability of seeing a test statistic this extreme, or more extreme, if \(H_0\) were true.

What if we had 15,000 students, not ?

With a huge sample, almost any difference becomes statistically significant — the CI narrows to nearly nothing, and even a 1ms gap could reject \(H_0\).

Statistical significance ≠ practical significance. At scale, the question shifts from “is there a difference?” to “is the difference big enough to matter?” — external validity remains just as important as it was at n=.

Recap — how do we know a difference is real?

  • Sampling distributions: any statistic computed from a sample has its own distribution across repeated samples from the same DGP — that’s why a single estimate is never the whole story
  • Standard error: a formula (\(SE = SD/\sqrt{n}\)) or the bootstrap — two ways to estimate how much a statistic would vary from sample to sample
  • Confidence intervals: statistic ± critical value × SE — a range built so that, over many samples, it contains the true value a chosen % of the time
  • Hypothesis testing: state \(H_0\), compute a t-statistic, compare it to a critical value (±1.96 for 5%) or read off the p-value directly
  • Two ways to be wrong: false positives (Type I) and false negatives (Type II) — the test is designed to protect against false positives
  • Statistical ≠ practical significance: with a big enough sample almost anything is “significant” — effect size and external validity still matter
