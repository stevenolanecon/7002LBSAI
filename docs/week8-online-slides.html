Count outcomes

The workshop covered a 0/1 outcome. What about an outcome that can be 0, 1, 2, 3… with no natural ceiling?

How many bikes today?

Business question: a bike-share operator needs to plan how many bikes to have available each day. Rentals range from 22 on the worst day to 8,714 on the best — driven by weather, season, and whether it’s a working day.

This is real UCI data: 731 days, daily rental counts (cnt), temperature, humidity, windspeed, season, and working-day status.

Same logic, new distribution

Everything from the workshop still applies — a link function connects a linear index to the outcome, and raw coefficients aren’t directly interpretable.

  • Binary y: link function keeps predictions between 0 and 1 (logistic or normal CDF)
  • Count y: link function needs to keep predictions non-negative — no upper bound needed, but never below zero
  • The natural choice: \(E[y|x] = \exp(\beta_0 + \beta_1 x_1 + \dots)\) — the log link

Poisson regression

\[\ln(E[y|x]) = \beta_0 + \beta_1 x_1 + \dots\]

  • The Poisson distribution is the standard choice for count data — same role here as the logistic/normal assumption played for binary y
  • Fit by maximum likelihood, same idea as logit and probit
  • Because of the log link, coefficients are additive on the log scale, multiplicative on the count scale

Interpreting via the incidence rate ratio

Exponentiating a coefficient converts it into an incidence rate ratio (IRR):

\[IRR = \exp(\beta_1)\]

A one-unit increase in \(x_1\) multiplies the expected count by \(IRR\) — not adds to it. Same underlying logic as an odds ratio from logit, just for counts instead of binary outcomes.

  • \(IRR > 1\): expected count goes up
  • \(IRR < 1\): expected count goes down
  • \(IRR = 1\): no effect

Fitting it, in code

import statsmodels.api as sm
import statsmodels.formula.api as smf

poisson_model = smf.glm(
    "cnt ~ temp_c + workingday + C(season_name) + windspeed + hum",
    data=df,
    family=sm.families.Poisson()

irr = np.exp(poisson_model.params)

A closer look

Is Poisson actually a good fit here?

Poisson’s hidden assumption

Poisson regression assumes equidispersion: the variance of \(y\) equals its mean, \(Var(y|x) = E(y|x)\).

  • Ratio: ×

The variance is nowhere close to the mean — this is severe overdispersion. Daily rental counts are the sum of thousands of individual decisions, which naturally vary far more than a simple Poisson process would predict.

Why this matters

Fitting a plain Poisson model when the data is this overdispersed doesn’t just look untidy — it makes every standard error too small, which makes every result look more certain than it actually is.

We need a model that keeps the same log link and the same IRR interpretation, but doesn’t force variance to equal the mean.

Negative binomial — the fix

  • Same log link, same IRR interpretation — nothing about reading the model changes
  • Adds one extra parameter, α, that lets the variance exceed the mean instead of forcing them to be equal
  • The practical rule: when the data is this overdispersed, reach for negative binomial, not plain Poisson — you don’t need to derive why, just recognise the symptom (variance ≫ mean) and know the fix exists

Fitting it, in code

nb_model = smf.negativebinomial(
    "cnt ~ temp_c + workingday + C(season_name) + windspeed + hum",
    data=df
).fit()

Other kinds of y, briefly

  • Ordinal/nominal outcomes (e.g. satisfaction ratings, product categories) can sometimes be recast as binary — “top box vs. not” — trading some information for a model you already know how to run
  • Duration variables (time until an event) are often censored — you don’t observe the full duration for everyone. Running OLS on censored durations gets the direction right but not the magnitude. Converting to a binary “did the event happen by time T” is often the pragmatic choice

Summary

  • A count outcome needs a link function that keeps predictions non-negative — the log link, giving Poisson regression
  • Coefficients are read via the incidence rate ratio, \(\exp(\beta)\) — the same logic as an odds ratio, just multiplicative on counts
  • Poisson assumes variance equals the mean — check this before trusting the standard errors, since real data is often far more dispersed than that
  • Negative binomial is the standard fix, and it can move both the standard errors and the estimates themselves
