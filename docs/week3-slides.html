When y met x

Weeks 1–2 looked at one variable at a time. Today: how do two variables move together — and when should we trust that?

A shortcut for HR

The reaction-time test works, but it takes ten trials per person to administer. HR wants something faster: “find us a quick physical measurement that predicts reaction time, and we’ll screen candidates on that instead.”

That’s why we collected index finger length back in Week 1.

Is it a fast, reliable stand-in for the real test? Today gives us the tools to answer that properly — and the discipline not to answer it too quickly.

When y met x

The y and the x

Much of data analysis is about comparing values of a y variable across values of an x variable — uncovering patterns of association.

  • By convention, y is the variable we’re interested in; x is what we compare across
  • Goal 1 — prediction: use x to predict y, without needing to know why
  • Goal 2 — causal effect: learn what would happen to y if we changed x

HR’s proxy-test idea is a prediction goal, dressed up as if it were free of that distinction. Keep watching for where the two goals get blurred.

Source: Békés & Kézdi (2021), Data Analysis for Business, Economics, and Policy, Ch. 4

Conditional probability

Conditioning on x

Comparison → conditioning. Comparing y by values of x means we condition y on x — x is the conditioning variable, y is the outcome variable.

Worked example: 20 students, 12 use a Phone, and 9 of those 12 had caffeine.

Joint probability — the chance both things happen together:

\[P(A \text{ and } B) = \frac{9}{20} = 0.45\]

Conditional probability — the chance of A, restricted to the cases where B happened:

\[P(A \mid B) = \frac{P(A \text{ and } B)}{P(B)} = \frac{0.45}{12/20} = \frac{0.45}{0.6} = 0.75\]

Independence — A and B are independent if knowing one tells you nothing about the other: \(P(A \mid B) = P(A)\). Here, overall \(P(\text{Caffeine}) = 11/20 = 0.55\), but \(P(\text{Caffeine} \mid \text{Phone}) = 0.75\) — not equal, so not independent in this example.

When A and B are not independent, \(P(A \text{ and } B) \neq P(A) \times P(B)\) — that shortcut only holds under independence (\(0.6 \times 0.55 = 0.33\), not the real \(0.45\)). The formula that always holds is the one above, rearranged: \(P(A \text{ and } B) = P(A \mid B) \times P(B)\).

Source: Békés & Kézdi (2021), Ch. 4

Task — condition on our own data

On paper, using the table above: what is \(P(\text{Caffeine} = \text{Yes} \mid \text{Device} = \text{Phone})\)?

Does knowing someone’s device change your guess about their caffeine use? How much would you trust that conclusion, given how many observations it’s based on?

Independence is not a yes/no question you can answer from a table this small. Any real sample will show some numerical gap between the conditional and marginal probabilities, purely by chance — even when the true population relationship is independence. Telling a real pattern from sampling noise is exactly what Week 2’s tools (standard errors, hypothesis tests) are for. With this few observations, “we can’t tell yet” is the honest answer, not a verdict either way.

Conditional distribution and expectation

The conditional mean

The conditional expectation of y for a given value of x:

\[E[y \mid x]\]

  • The mean of y, computed separately for each value (or group) of x
  • With few x values, a histogram or box plot per group works well (Week 1)
  • With many x values — like finger length in mm — group into bins first

Source: Békés & Kézdi (2021), Ch. 4

What we’ll actually do

Two error patterns, not one random mess:

  • Too small (under 10mm): almost certainly centimetres entered where millimetres were asked for — a 6.9 is very plausibly a real 69mm finger, just in the wrong unit
  • Too large (700–900mm): almost certainly an extra typed digit — 900 is very plausibly a real 90mm finger with a stray zero

We impute, not drop. Both patterns have an identifiable, high-confidence correction (×10 or ÷10) that lands the value squarely back in the range every other student’s real measurement falls in — dropping 5 of 24 students (over 20% of the class) would throw away perfectly good reaction-time data for those students, for a finger-length problem that’s actually fixable.

This wouldn’t be the right call for every data problem — imputation only makes sense when you have a specific, well-justified reason to believe what the correct value should be. A value that’s merely unusual, with no diagnosable cause, is a much better candidate for dropping (or for the “keep it, it’s a genuine feature of the process” option from Week 1’s own three-question framework) than for guessing a replacement.

Scatter, covariance, correlation

Scatterplot and bin-scatter

A scatterplot puts two variables on two axes, one dot per observation. It’s one of the most powerful ways to see whether a relationship exists between two variables — no formula required, just look.

Does logging reaction time help?

Week 1 found reaction time is closer to log-normal than normal — a floor, no ceiling, long right tail. Gabor’s own case study logs a skewed variable for exactly this reason: it stretches out the crowded end and compresses the tail, so a pattern against x is easier to read.

function fitLine(rows, yOf) {
  const xs = rows.map(d => d.sleep_hours), ys = rows.map(yOf)
  const mx = d3.mean(xs), my = d3.mean(ys)
  const b = d3.sum(xs.map((x, i) => (x - mx) * (ys[i] - my))) / d3.sum(xs.map(x => (x - mx) ** 2))
  const a = my - b * mx
  const yhat = xs.map(x => a + b * x)
  const ssRes = d3.sum(ys.map((y, i) => (y - yhat[i]) ** 2))
  const ssTot = d3.sum(ys.map(y => (y - my) ** 2))
  const r2 = 1 - ssRes / ssTot
  const [x0, x1] = d3.extent(xs)
  return { line: [{ x: x0, y: a + b * x0 }, { x: x1, y: a + b * x1 }], r2 }
}

Covariance

In plain language: covariance asks whether x and y tend to move together — when one is above its own average, is the other usually above its average too?

\[Cov[x,y] = \frac{\sum_i (x_i - \bar{x})(y_i - \bar{y})}{n-1}\]

  • Multiplies each observation’s deviation from the x-mean by its deviation from the y-mean, and averages
  • Positive when x and y tend to deviate from their means in the same direction
  • Can be any positive or negative number — units depend on the units of x and y
  • Like the SD back in Week 1, this divides by \(n-1\), not \(n\) — the same small-sample correction, applied here too
{
  const rows = student_summary.filter(d => d.finger_mm != null && !isNaN(d.finger_mm))
  if (rows.length < 3) return html`<div class="instructions-box">Not enough finger-length data yet.</div>`
  const mx = d3.mean(rows, d => d.finger_mm), my = d3.mean(rows, d => d.mean_rt)
  const colored = rows.map(d => ({ ...d, sign: (d.finger_mm - mx) * (d.mean_rt - my) >= 0 ? "Same sign (+)" : "Opposite sign (−)" }))

  return Plot.plot({
    height: 310,
    marginLeft: 60,
    x: { label: "Finger length (mm)" },
    y: { label: "Mean reaction time (ms)" },
    color: { domain: ["Same sign (+)", "Opposite sign (−)"], range: ["#2d6a4f", "#e63946"], legend: true },
    marks: [
      Plot.ruleX([mx], { stroke: "#999", strokeDasharray: "4,3" }),
      Plot.ruleY([my], { stroke: "#999", strokeDasharray: "4,3" }),
      Plot.dot(colored, { x: "finger_mm", y: "mean_rt", fill: "sign", r: 6, fillOpacity: 0.85,

}

Dashed lines = each variable’s own mean. A point’s contribution is \((x_i - \bar{x})(y_i - \bar{y})\) — green = both deviations the same sign, positive product; red = opposite signs, negative product. Covariance is the average of all these products.

Source: Békés & Kézdi (2021), Ch. 4

Correlation

In plain language: correlation asks the same question as covariance — do x and y move together — but reports the answer on a fixed scale from −1 to 1, so it’s comparable no matter what units x and y are measured in.

The standardised version of the covariance — divide by the product of the standard deviations:

\[Corr[x,y] = \frac{Cov[x,y]}{SD[x] \, SD[y]} \qquad -1 \leq Corr[x,y] \leq 1\]

Rough guide: below 0.2 is weak, above 0.7 is generally strong.

Task — calculate the correlation

Using your covariance from two slides ago, and the SD of each variable: calculate the correlation coefficient.

{
  const rows = student_summary.filter(d => d.finger_mm != null && !isNaN(d.finger_mm))
  if (rows.length < 3) return html`<p style="color:#aaa;">Will compute automatically once enough data is in.</p>`
  const xs = rows.map(d => d.finger_mm), ys = rows.map(d => d.mean_rt)
  const mx = d3.mean(xs), my = d3.mean(ys)
  const cov = d3.sum(xs.map((x,i) => (x - mx) * (ys[i] - my))) / (xs.length - 1)
  const corr = cov / (d3.deviation(xs) * d3.deviation(ys))

}

Is it causal?

Where does the variation in x come from?

Comparison requires variation in the conditioning variable — and where that variation comes from matters enormously.

Experimental data

  • A treatment is assigned, often randomly
  • Differences in y are attributable to the treatment alone
  • e.g. randomly assign aspirin vs. placebo

Observational data

  • x varies because of people’s own choices, circumstances, history
  • Many other things may differ alongside x
  • e.g. people who already take aspirin routinely may do so because of prior health risk

Almost everything in business analytics is observational. Finger length is one of the few genuinely fixed, “as-if-random” variables we’re likely to find — most x’s we’ll meet from here on are not.

Source: Békés & Kézdi (2021), Ch. 4

Measuring what you can’t observe directly

Latent variables

Some concepts — attitude, ability, management quality — can’t be measured with a single variable. They’re latent: real, but only indirectly observable through several proxies at once.

  • Use one variable — simple, but throws away information
  • Average several (as z-scores) — standardise first, then average; simple and transparent
  • PCA — weights each variable by how well it captures the shared pattern; typically close to the simple average in practice

Source: Békés & Kézdi (2021), Ch. 4

Use one variable

The simplest approach: pick a single observable variable and treat it as a stand-in for the thing you can’t measure directly.

  • Postcode as a proxy for socioeconomic background
  • Job tenure as a proxy for “experience”
  • Finger length as a proxy for manual dexterity — this module’s own opening example

It’s simple, and sometimes good enough. But a single proxy only ever captures part of the underlying concept — whatever it misses is thrown away, and if the proxy is a weak one, most of the concept goes with it.

Task — our own reaction times aren’t purely mechanical. What latent variables might actually be driving them — alertness, familiarity with the device, motivation on the day? What proxies do we already have sitting in our own data for any of these?

Standardisation — the z-score

Sleep (hours), energy (1–10), grip strength (kg) — three completely different scales. You can’t just add 8.5 hours of sleep to a grip strength of 33kg and call the result “alertness.” Standardisation fixes this: it converts any variable onto one common, unit-free scale, based on how far each value sits from its own average.

\[z = \frac{x - \bar{x}}{SD[x]}\]

  • Subtract the mean: \(z = 0\) sits exactly at the average
  • Divide by the SD: \(z\) is now measured in “number of SDs from the mean” — the same scale, whatever the variable’s original units
  • \(z = +1\) means one SD above average; \(z = -1.5\) means one and a half SDs below
  • Every standardised variable now lives on the same scale, and can be safely compared or averaged

Standardisation — worked example

Sleep hours for the six people we’ll use next:

{
  const people = [
    { name: "Amara", sleep: 8.5 },
    { name: "Ben",    sleep: 5.0 },
    { name: "Chidi",  sleep: 7.0 },
    { name: "Dana",   sleep: 4.5 },
    { name: "Elin",   sleep: 9.0 },
    { name: "Femi",   sleep: 6.0 },
  ]
  const vals = people.map(p => p.sleep)
  const m = d3.mean(vals)
  const s = d3.deviation(vals) * Math.sqrt((vals.length - 1) / vals.length)
  const rows = people.map(p => ({ ...p, z: (p.sleep - m) / s }))

  return html`<p style="font-family:sans-serif;font-size:0.85em;margin-bottom:6px;">Mean = ${m.toFixed(2)}h, SD = ${s.toFixed(2)}h</p>
  <table style="width:70%;margin:0 auto;border-collapse:collapse;font-family:sans-serif;font-size:0.8em;">
    <thead><tr style="background:#1a1a2e;color:white;">
      <th style="padding:1px 14px;text-align:left;">Person</th>
      <th style="padding:1px 14px;text-align:right;">Sleep (h)</th>
      <th style="padding:1px 14px;text-align:right;">z(sleep)</th>
    </tr></thead>
    <tbody>
      ${rows.map((r,i) => `<tr style="${i%2===1?'background:#fafafa;':''}border-bottom:1px solid #eee;">
        <td style="padding:1px 14px;">${r.name}</td>
        <td style="padding:1px 14px;text-align:right;">${r.sleep}</td>
        <td style="padding:1px 14px;text-align:right;${r.z>=0?'color:#2d6a4f;':'color:#e63946;'}">${r.z >= 0 ? '+' : ''}${r.z.toFixed(2)}</td>
      </tr>`).join('')}
    </tbody>
  </table>`
}

Amara slept the most, and her \(z\approx+1.1\) says so directly: about one SD above the group’s own average. Dana’s \(z\approx-1.3\) says the opposite. That’s the whole idea — the raw hours are gone, replaced by a common yardstick.

Apply the same z-score formula to all three proxies, then average the three z-scores per person.

{
  const people = [
    { name: "Amara", sleep: 8.5, energy: 9, grip: 33 },
    { name: "Ben",    sleep: 5.0, energy: 4, grip: 32 },
    { name: "Chidi",  sleep: 7.0, energy: 6, grip: 35 },
    { name: "Dana",   sleep: 4.5, energy: 3, grip: 30 },
    { name: "Elin",   sleep: 9.0, energy: 8, grip: 31 },
    { name: "Femi",   sleep: 6.0, energy: 5, grip: 34 },
  ]
  const z = vals => { const m = d3.mean(vals), s = d3.deviation(vals) * Math.sqrt((vals.length-1)/vals.length); return vals.map(v => (v - m) / s) }

Task — using the same formula and the grip-strength values from the table above, calculate \(z(\text{grip})\) for each person. Then average all three z-scores to get one “alertness” score per person.

Average several (as z-scores) — answer

{
  const people = [
    { name: "Amara", sleep: 8.5, energy: 9, grip: 33 },
    { name: "Ben",    sleep: 5.0, energy: 4, grip: 32 },
    { name: "Chidi",  sleep: 7.0, energy: 6, grip: 35 },
    { name: "Dana",   sleep: 4.5, energy: 3, grip: 30 },
    { name: "Elin",   sleep: 9.0, energy: 8, grip: 31 },
    { name: "Femi",   sleep: 6.0, energy: 5, grip: 34 },
  ]
  const z = vals => { const m = d3.mean(vals), s = d3.deviation(vals) * Math.sqrt((vals.length-1)/vals.length); return vals.map(v => (v - m) / s) }

PCA

Same six people, same three proxies. Instead of weighting every variable equally, PCA looks at how the variables correlate with each other, and finds the one weighted combination that captures as much of their shared variation as possible.

{
  const rows = [
    { v: "Sleep",  sleep: 1.00, energy: 0.97, grip: 0.20 },
    { v: "Energy", sleep: 0.97, energy: 1.00, grip: 0.25 },
    { v: "Grip",   sleep: 0.20, energy: 0.25, grip: 1.00 },
  ]
  return html`<table style="width:60%;margin:0 auto;border-collapse:collapse;font-family:sans-serif;font-size:0.9em;">
    <thead><tr style="background:#1a1a2e;color:white;">
      <th style="padding:8px 16px;text-align:left;">Correlation</th>
      <th style="padding:8px 16px;text-align:right;">Sleep</th>
      <th style="padding:8px 16px;text-align:right;">Energy</th>
      <th style="padding:8px 16px;text-align:right;">Grip</th>
    </tr></thead>
    <tbody>
      ${rows.map((r,i) => `<tr style="${i%2===1?'background:#fafafa;':''}border-bottom:1px solid #eee;">
        <td style="padding:7px 16px;font-weight:700;">${r.v}</td>
        <td style="padding:7px 16px;text-align:right;">${r.sleep.toFixed(2)}</td>
        <td style="padding:7px 16px;text-align:right;">${r.energy.toFixed(2)}</td>
        <td style="padding:7px 16px;text-align:right;">${r.grip.toFixed(2)}</td>
      </tr>`).join('')}
    </tbody>
  </table>`
}

Sleep and energy move together closely (0.97); grip strength barely tracks either (0.20–0.25) — a noisier signal for the same underlying “alertness.”

PCA notices this automatically:

Variable Equal-weight average PCA weight
Sleep 0.33 0.41
Energy 0.33 0.41
Grip 0.33 0.18

It down-weights the noisier proxy — something a simple average, by construction, can’t do.

The two composite scores still end up highly correlated (≈0.98 here) — usually true in practice. That’s exactly why Gabor & Kézdi recommend the z-score average for everyday use, and treat PCA as a robustness check rather than a first choice.

Source: Békés & Kézdi (2021), Ch. 4

AI and finding patterns

GenAI is genuinely useful for a first pass over a new dataset — spotting candidate patterns quickly, the way a quick script or profiler would.

Where it’s weaker: judging whether a correlation is meaningfully weak or strong, and knowing which pattern is worth pursuing in the first place. That judgment is still yours.
