olsFit = function(X, y) {
  const n = X.length, k = X[0].length + 1
  const design = X.map(row => [1, ...row])
  const XtX = Array.from({length: k}, (_, i) => Array.from({length: k}, (_, j) => d3.sum(design.map(r => r[i] * r[j]))))
  const Xty = Array.from({length: k}, (_, i) => d3.sum(design.map((r, idx) => r[i] * y[idx])))
  const A = XtX.map((row, i) => [...row, Xty[i]])
  for (let col = 0; col < k; col++) {
    let piv = col
    for (let r = col + 1; r < k; r++) if (Math.abs(A[r][col]) > Math.abs(A[piv][col])) piv = r
    const tmp = A[col]; A[col] = A[piv]; A[piv] = tmp
    for (let r = 0; r < k; r++) {
      if (r === col) continue
      const factor = A[r][col] / A[col][col]
      for (let c = col; c <= k; c++) A[r][c] -= factor * A[col][c]
    }
  }
  const coefs = A.map((row, i) => row[k] / row[i])
  const fitted = design.map(r => d3.sum(r.map((v, i) => v * coefs[i])))
  const resid = y.map((yi, i) => yi - fitted[i])
  return { coefs, fitted, resid, n, k }
}

Multiple regression

Finger length alone barely moved the needle. What if device or caffeine matter too — and are tangled up with finger length itself?

One x at a time was never the whole story

HR has separate regressions: reaction time on finger length, reaction time on device. Someone asks: which one actually matters?

Naive answer: run each regression separately, compare the slopes, done.

Why it’s not that simple: if finger length and device happen to be correlated in our sample — say, one device tends to attract a particular hand-size group — each regression is silently absorbing some of the other variable’s effect. We can’t tell which x is doing the work until we ask both questions at once.

Why more than one x?

Three reasons to add a second x

  • Broader patterns — plain exploratory work, understanding the data more fully
  • Closer to comparing similar observations — holding one variable fixed while looking at another gets nearer to ceteris paribus, “all else equal”
  • Better prediction — more of the variation in y gets explained

Source: Békés & Kézdi (2021), Ch. 10

Two x variables

\[y^E = \beta_0 + \beta_1 x_1 + \beta_2 x_2\]

  • \(\beta_1\): the difference in average y across observations that differ in \(x_1\) but share the same \(x_2\)
  • \(\beta_2\): the same idea, the other way round
  • We can now compare observations that are similar in one explanatory variable, to isolate what the other one is doing

Source: Békés & Kézdi (2021), Ch. 10

Omitted variable bias

Comparing the simple and multiple slope

\[y^E = \alpha + \beta x_1 \qquad\qquad y^E = \beta_0 + \beta_1 x_1 + \beta_2 x_2\]

An intermediate step — regress \(x_2\) on \(x_1\) itself, slope \(\delta\):

\[x_2^E = \gamma + \delta x_1\]

Substituting back in gives a precise relationship between the two versions of the \(x_1\) slope:

\[\beta - \beta_1 = \delta\beta_2\]

Source: Békés & Kézdi (2021), Ch. 10

Omitted variable bias, named

\[\beta - \beta_1 = \delta\beta_2\]

  • This gap is the omitted variable bias (OVB)
  • If you care about \(\beta_1\), the simple regression \(y^E=\alpha+\beta x_1\) is the wrong regression — it omits \(x_2\)
  • The bias is exactly zero only if \(x_1\) and \(x_2\) are uncorrelated (\(\delta=0\)), or \(x_2\) has no effect on y in the full model (\(\beta_2=0\))

Neither condition is something you can assume — it has to be checked, or reasoned about.

Source: Békés & Kézdi (2021), Ch. 10

Worked example: beer sales and price

A scenario where we can control the truth: monthly change in our log price (\(x_1\)) and a competitor’s log price (\(x_2\)) tend to move together, both driving change in log sales (y). Simulate it, and check the OVB formula holds exactly.

import numpy as np, pandas as pd
import statsmodels.formula.api as smf

rng = np.random.default_rng(42)
competitor_price = rng.normal(0, 2.0, 300)
our_price        = 0.8 * competitor_price + rng.normal(0, 1.2, 300)   # correlated with competitor's
sales            = -3*our_price + 3*competitor_price + rng.normal(0, 2.5, 300)  # true betas: -3, +3
df = pd.DataFrame({'sales': sales, 'our_price': our_price, 'competitor_price': competitor_price})

simple = smf.ols('sales ~ our_price', data=df).fit()
multi  = smf.ols('sales ~ our_price + competitor_price', data=df).fit()
aux    = smf.ols('competitor_price ~ our_price', data=df).fit()   # x2 on x1, per the formula above

beta (simple)     = -0.949
beta1 (multiple)  = -3.273
beta2 (multiple)  = 3.125
delta (x2 on x1)  = 0.744

beta − beta1 = 2.3244    delta×beta2 = 2.3244

The two sides match exactly — \(\hat\beta-\hat\beta_1\) and \(\hat\delta\hat\beta_2\) are the same calculation, done two different ways. And since we built this dataset ourselves, we know the simple regression really is biased: the true effect of our own price is \(-3\), but \(\hat\beta\) lands nowhere near it — because it’s silently absorbing the competitor-price effect too, through the correlation between the two.

Language: conditioning, controlling, confounding

  • We measure differences in y by \(x_1\), conditional on \(x_2\) — or controlling for \(x_2\)
  • When a variable that belongs in the model is left out, it’s an omitted variable
  • If it’s correlated with both \(x_1\) and y, it’s a confounder — the slope on \(x_1\) is confounded

Source: Békés & Kézdi (2021), Ch. 10

Multicollinearity — a different problem

Multicollinearity, defined

Multicollinearity: two or more explanatory variables in the same regression are strongly correlated with each other.

  • It does not bias any coefficient — β̂ is still right, on average
  • It inflates the standard errors — β̂ becomes imprecise, harder to pin down
  • Intuition: if \(x_1\) and \(x_2\) move together almost every time, there’s barely any data where one is high and the other is low — and that’s exactly the comparison OLS needs to estimate their separate slopes

Contrast with Section B: OVB is about what’s missing from the model. Multicollinearity is about what’s already in it, just tangled together.

Source: Békés & Kézdi (2021), Ch. 10

Where the standard error comes from

\[SE(\hat\beta_1) = \frac{Std[e]}{\sqrt{n}\cdot Std[x_1]\cdot\sqrt{1-R_1^2}}\]

  • Same ingredients as Week 5’s simple-regression SE — fit, spread of \(x_1\), sample size
  • New: \(R_1^2\) — the R² from regressing \(x_1\) on \(x_2\) (and any other x’s). The more \(x_1\) is explained by the other regressors, the bigger this term, the bigger the SE

Source: Békés & Kézdi (2021), Ch. 10

Perfect vs. imperfect collinearity

  • Perfect collinearity — \(x_1\) is an exact linear function of \(x_2\). Coefficients literally can’t be calculated; software drops one variable for you
  • Multicollinearity — strong but imperfect correlation between explanatory variables. Coefficients and SEs can still be computed — but the SEs may be large

Intuition: multicollinearity means there aren’t many observations that differ in \(x_1\) while staying similar in \(x_2\) — so there’s little clean information left to estimate \(\beta_1\) precisely.

Source: Békés & Kézdi (2021), Ch. 10

Naming it: VIF

Software usually calls this number the Variance Inflation Factor:

\[VIF_k = \frac{1}{1-R_k^2}\]

  • The exact same \(R_k^2\) from two slides ago — just flipped into one number per variable
  • Common rule of thumb: VIF > 10 flags a real problem (some use a stricter >5)
  • One line in statsmodels: variance_inflation_factor(X, k)

The VIF trap

A high VIF does not mean “drop this variable.” If it’s a genuine confounder, dropping it to fix a precision problem reintroduces the bias problem from Section B — often a worse trade.

The honest response to a high VIF is usually: report it, keep the variable if the causal story needs it, and be upfront that the estimate is imprecise. VIF is a diagnostic, not a decision rule.

What to actually do about it

  • Look at pairwise correlations (or a correlation heatmap) early, before modelling
  • Drop one of a highly correlated pair, or combine them (average, or a z-score index)
  • Mostly a small-sample problem — hundreds to a few thousand observations
  • With many x’s: check \(R_k^2\) for each variable regressed on all the others; drop if very high

Source: Békés & Kézdi (2021), Ch. 10

The distinction that matters

Omitted variable bias Multicollinearity
What it is Leaving out a variable that belongs in the model Including two variables that are strongly correlated
What it breaks The point estimate itself — wrong on average Precision — the estimate is right on average, just noisy
Does more data fix it? No. Same bias at any sample size Yes. More data narrows the SE back down
Direction known? Depends on \(\delta\) and \(\beta_2\) — could go either way N/A — SE inflates, doesn’t shift the estimate

Confusing these two is the single most common mistake in reading regression output. One is a bias problem you fix by adding the right variable. The other is a precision problem you sometimes fix by removing one.

Testing more than one coefficient

Individual coefficients — same as before

Each \(\hat\beta_k\) gets its own CI and t-test, exactly as in Week 5:

\[CI(\hat\beta_k)_{95\%} = \hat\beta_k \pm 2\,SE(\hat\beta_k) \qquad\qquad t=\frac{\hat\beta_k}{SE(\hat\beta_k)}\]

The only change is where \(SE(\hat\beta_k)\) comes from — the formula with the \(\sqrt{1-R_k^2}\) term from Section C.

Testing several coefficients together

Sometimes the question isn’t about one coefficient, but a group of them — e.g. “are all the geography dummies jointly zero?”

The F-test answers this. Individually, none of the coefficients might be statistically distinguishable from zero — but jointly, they might still be.

The global F-test — are all slope coefficients zero? — is reported by default in most software. Gabor & Kézdi’s own advice: don’t lean on it too heavily. R² tells you almost the same thing, more simply, for that particular question.

Source: Békés & Kézdi (2021), Ch. 10

Categorical variables, properly

k categories, k − 1 dummies

A categorical x with values low/medium/high becomes two binary variables — one category left out as the reference:

\[y^E = \beta_0 + \beta_1 x_{medium} + \beta_2 x_{high}\]

  • \(\beta_0\) — average y in the reference category (low)
  • \(\beta_1\) — difference between medium and low
  • \(\beta_2\) — difference between high and low

Include all k dummies (no reference left out) and you get the dummy variable trap — perfect collinearity with the intercept, and the model can’t be estimated.

Source: Békés & Kézdi (2021), Ch. 10

Choosing a reference category

  • Substantive guide — pick whatever you naturally want everything else compared to (the home market, the base product, the lowest tier)
  • Statistical guide — pick a category with plenty of observations. A thin reference category means every comparison against it inherits a large SE

Source: Békés & Kézdi (2021), Ch. 10

Interactions: different slopes for different groups

When the pattern itself varies by group

An interaction asks: does the relationship between y and \(x_1\) differ depending on a second variable, D? D is sometimes called a moderator.

Examples: does customer rating relate to hotel price differently by star category? Does a drug’s effect vary with patient age? Does the finger-length/reaction-time pattern differ by device?

Source: Békés & Kézdi (2021), Ch. 10

The structural model

\[y^E = \beta_0 + \beta_1 x_1 + \beta_2 D + \beta_3\,(x_1 \times D)\]

  • When \(D=0\): \(y^E = \beta_0 + \beta_1 x_1\) — intercept \(\beta_0\), slope \(\beta_1\)
  • When \(D=1\): \(y^E = (\beta_0+\beta_2) + (\beta_1+\beta_3)\,x_1\) — intercept shifts by \(\beta_2\), slope shifts by \(\beta_3\)

\(\beta_3\) is the answer to the interaction question — literally the difference in slopes between the two groups. It gets its own SE, its own t-stat, its own CI, exactly like any other coefficient.

Source: Békés & Kézdi (2021), Ch. 10

Does a near-zero coefficient mean no gap?

female = −0.036, not even statistically distinguishable from zero (p ≈ 0.30). Does this mean the gender gap has disappeared? What does female × age = −0.003, strongly significant, tell you that the female coefficient alone doesn’t?

Reread the structural model: at \(D=1\) (female), the slope on age is \(\beta_1+\beta_3\), not \(\beta_1\). The “female” coefficient alone only describes the gap at age zero — a meaningless, never-observed point. The real story is in \(\beta_3\).

Is it (more) causal?

Ceteris paribus is a destination, not a guarantee

Conditioning on more variables gets us closer to comparing “apples to apples,” even in observational data. But:

  • Ceteris paribus means conditioning on every relevant confounder
  • A regression can only condition on what’s actually in the dataset, measured the way it happens to be measured
  • Conditioning on everything is impossible in general. Multiple regression is hardly ever truly ceteris paribus

Source: Békés & Kézdi (2021), Ch. 10

Not every correlated variable belongs

Question: to see how TV advertising affects sales, should you control for how many people viewed the advert?

No. Fewer views is part of why less advertising hurts sales — it’s not a confounder, it’s a step in the causal chain itself. Controlling for it would control away the very thing you’re trying to measure.

These are sometimes called bad controls. Telling a genuine confounder from a bad control by eye is genuinely hard — we’ll get a proper diagram for reasoning about this in Week 9.

Source: Békés & Kézdi (2021), Ch. 10

Language, still

Even with five variables conditioned on, a regression is still a comparison of conditional means — not a randomized experiment.

Same rule as Week 4: avoid “effect,” avoid “increases/decreases,” in observational data. “Higher finger length is associated with a difference of X ms, holding device and caffeine fixed” is honest. “Finger length affects reaction time” is not — not yet.

Prediction, overfitting, and choosing variables

The ŷ–y plot

\[\hat y = \hat\beta_0+\hat\beta_1x_1+\hat\beta_2x_2+\dots\]

A scatterplot of \(\hat y\) (predicted) against actual y, with the 45° line:

  • Points right of the line: overpredicted
  • Points left of the line: underpredicted
  • More informative than R² alone — it shows where the model struggles, not just how much

Our own predictions vs. reality

Overfitting and choosing variables

  • R² mechanically rises every time you add a variable — even pure noise. It can never fall
  • Overfitting: capturing patterns specific to this dataset that won’t hold up elsewhere
  • Purpose changes the rule: for a causal question, keep confounders that matter for comparison even if imprecise; for prediction, value simplicity and generalisability over fit

Rough sample-size guide (Gabor & Kézdi): 20–40 observations supports about 1–2 variables; 50–100 supports 2–4; a few hundred supports 5–10; a few thousand can support dozens, including dummies and interactions. Formal criteria like BIC penalise added variables directly — more in Week 10.

Source: Békés & Kézdi (2021), Ch. 10

Summary

  • Multiple regression is a linear model with several x’s, letting us compare observations that are similar in one variable while differing in another
  • Omitted variable bias (leaving out a relevant, correlated variable) and multicollinearity (including two correlated variables) are opposite problems — bias vs. precision — and the fix for one is not the fix for the other
  • It gets us closer to a causal comparison, never all the way there
  • More variables always raises R² — that’s not the same as a better model
