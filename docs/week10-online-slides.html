Model building for prediction

The workshop built the toolbox on six clean predictors and 281 cars. This session: what happens with dozens of candidate variables — and 4,393 real Airbnb listings.

Label engineering: choosing the target

Before a single predictor gets chosen, there’s a decision about y itself. Sometimes the business question settles it outright — the price of the hotel room is the price of the hotel room. Often it genuinely needs deciding: level, or log?

  • Price is usually closer to a linear relationship with its predictors when expressed in log terms than in levels
  • Log differences approximate percentage differences, and percentage differences in price are often more stable across very different kinds of listing than pound differences are
  • A technical bonus: log prices tend to sit closer to a normal distribution, which helps a linear regression approximate the average relationship well

Source: Békés & Kézdi (2021), Ch. 14

Converting a log prediction back

Fit np.log(price) ~ ... and the model predicts ln(price), not price. Exponentiating the prediction directly undershoots, systematically:

\[\hat y = e^{\widehat{\ln y}} \times e^{\hat\sigma^2/2}\]

Why the extra term: the regression predicts the average log price, but we want the average price itself — and because \(\ln\) is a curved (concave) function, the average of \(e^{\ln y}\) across many listings is not the same as \(e\) raised to the average \(\ln y\). The correction, built from the spread of the regression’s own residuals (\(\hat\sigma\)), puts that back.

Feature engineering

Building the right-hand side

What is feature engineering?

  • Once the target is settled, feature engineering decides the list of candidate predictors and the functional form each one enters in
  • It draws on two things at once: domain knowledge — what actually drives price for a short-let listing — and statistics, checking which choices the data itself supports
  • Gábor & Kézdi call it the most effort-intensive part of building a prediction model, and the part with the biggest payoff

Source: Békés & Kézdi (2021), Ch. 14

The checklist

  1. Missing values — random, or systematic? Impute with a flag column, don’t just drop the observation
  2. Categorical values — binary, or a small set of dummies
  3. Text — mine it for useful signal (a “seminar” keyword, say), otherwise leave it
  4. Functional form — polynomials, splines, logs — the same choices as the workshop, applied to many variables at once
  5. Interactions — worth thinking about, expensive to search exhaustively

Source: Békés & Kézdi (2021), Ch. 14

Real data: Airbnb, London

  • 4,393 Hackney-borough listings, March 2017 snapshot
  • Target: nightly price, in pounds (the textbook labels it dollars, but the listings are in pounds)
  • ~70 predictor candidates: capacity, room and property type, cancellation policy, review scores, and 50 individual amenity dummies (d_tv, d_petsallowed, d_elevatorinbuilding, …)

Source: Békés & Kézdi (2021), airbnb dataset, osf.io/qyca8

Selecting variables automatically

LASSO

We can’t try every model

  • Each candidate predictor is either in or out, so \(p\) candidates give \(2^p\) possible models. With 70 candidates that’s more than \(10^{21}\): far too many to try
  • By hand: domain knowledge drives the choice — interpretable, but slow, and impossible with many interactions
  • By algorithm: let the data suggest which variables earn their place

Building a model by hand

Even when an algorithm does the final selection, the groundwork is still done by hand:

  • Domain knowledge picks the key variables first — what plausibly drives price for a short-let listing, before any statistic gets consulted
  • Drop the garbage: comb through candidates and cut the ones with poor coverage, poor quality, or no plausible relevance
  • Check pairwise correlations — multicollinearity bites harder the smaller the dataset
  • Prefer variables that are cheap to keep updating — a model running in production has to be fed, not just fitted once
  • How far this can go depends on the ratio of variables to observations, not the raw count of either on its own

Source: Békés & Kézdi (2021), Ch. 14

What LASSO does

  • LASSO — Least Absolute Shrinkage and Selection Operator — picks variables to include in a regression automatically, built to produce good predictions and avoid overfitting
  • It’s a shrinkage method: every coefficient gets pulled towards zero, which reduces variance
  • It’s also a feature-selection method: some coefficients get pulled all the way to exactly zero, dropping that variable from the model entirely
  • Both happen at once, inside the same single fitting step — no separate “shrink” and “select” stages

The LASSO equation

LASSO adds a penalty to the usual OLS minimisation:

\[\min_\beta \left\{ \sum_{i=1}^{N}\left(y_i - \beta_0 - \sum_{j=1}^{k}\beta_j x_{ij}\right)^2 + \lambda\sum_{j=1}^{k}|\beta_j| \right\}\]

  • The first term is the familiar OLS objective: fit the data as closely as possible
  • The second is new: a penalty proportional to the sum of the absolute values of the coefficients
  • \(\lambda\) sets how much that penalty weighs against fit. \(\lambda = 0\) gives plain OLS back; larger \(\lambda\) pulls harder, and more variables drop out

Side note: LASSO vs. BIC

Both exist to balance fit against complexity — the same goal as the BIC column two slides ago — but they get there differently:

  • BIC scores a model after it’s been fitted, so you can compare several separately-built candidates and pick the one with the best in-sample measure of fit
  • LASSO doesn’t produce a score to compare models with. It alters the coefficients during fitting, so the penalty is already built into the one model it hands you

Source: Békés & Kézdi (2021), Ch. 14

Why some coefficients hit exactly zero

Every coefficient faces a trade: a bigger \(\beta_j\) may fit the data a little better, but it costs more penalty. Where that trade settles depends on how the penalty’s pull changes as \(\beta_j\) shrinks — and that’s where LASSO and ridge genuinely differ.

    Plot.line(d3.range(-2, 2.01, 0.05).map(b => ({b, p: b * b / 2, k: "Ridge: λβ²"})), {x: "b", y: "p", stroke: "k", strokeWidth: 2.5}),
    Plot.ruleX([0], {stroke: "#999"})
  ]
})
  • LASSO’s penalty (blue) is a straight line through zero. Its slope — the saving from nudging \(\beta_j\) a little closer to zero — is exactly the same whether \(\beta_j\) is large or already tiny. That constant pull never lets up, so the moment a variable’s contribution to fit drops below it, the best move is to push all the way to zero, not just partway
  • Ridge’s penalty (red) is a curve that flattens near zero. Its slope shrinks right along with \(\beta_j\), so the closer you get to zero, the weaker the incentive to go any further. Coefficients get small, but the pull fades out before they ever actually reach it

The cost: bias

  • OLS is unbiased. LASSO isn’t — that’s the trade it makes for lower variance
  • Unlike OLS, there’s no closed-form solution; an algorithm solves for \(\beta\) and \(\lambda\) together
  • \(\lambda\) itself is chosen by cross-validation: try many values, pick the one with the best CV RMSE

The two penalty shapes have names: LASSO’s is “L1,” ridge’s squared penalty is “L2.” Regularisation covers both.

Why classical inference fails after LASSO

LASSO gives coefficients but no standard errors or p-values — and that’s not an oversight, it’s unavoidable. Two separate things are going on:

  • Which variables survive is itself decided by the data. LASSO’s selection step and its coefficient estimates come from the same sample. Classical standard errors and p-values are built on the assumption that the model was fixed on paper before any data arrived — here, it wasn’t
  • So applied after LASSO, they understate the real uncertainty. This is called post-selection inference, and it doesn’t go away if you refit plain OLS on just the survivors and read that model’s p-values — the variables going in were still chosen by looking at this data first

Why LASSO is still reasonable

  • That’s fine for prediction: we judge the model on held-out RMSE, not on any one coefficient’s p-value
  • LASSO accepts a little bias for a lot less variance — exactly the right trade when the goal is predicting new cases, not estimating one specific effect
  • For a causal question (Week 9), choose the controls by reasoning about the diagram, not by letting LASSO pick them. LASSO is a prediction tool, not an inference tool

Post-prediction diagnostics

Holdout sets

One more split before you trust the number

  • Model selection (BIC, cross-validation) already uses the data — repeatedly
  • Best practice: carve off a holdout set right at the start, and don’t touch it until the very end
  • Work set: model building, model selection, training/test folds — all happen here
  • Holdout set: touched exactly once, to get an honest read on how the chosen model will do on genuinely new data

The workflow

  1. Split the original data into a work set and a holdout set
  2. Inside the work set: training/test folds, k-fold CV, model selection
  3. Re-estimate the winning model on the whole work set
  4. Apply it to the holdout set — untouched until now
  5. Evaluate: this is the honest estimate of live-data performance

M6’s CV RMSE beats M4’s by about £1, at the cost of 52 extra coefficients — and BIC, which penalises exactly that, prefers M4 by a wide margin (36,038 against 36,184). Neither answer is wrong; they’re optimising different things. This session’s call: M6, because the stated goal is predicting price as accurately as possible, and the extra accuracy — however small — is the thing actually being asked for. A project valuing a simpler, cheaper-to-maintain model would reasonably choose M4 instead, and should say so explicitly rather than let the software’s default choice decide quietly.

Summary

  • Prediction with many candidate variables needs the same discipline as prediction with a few — just automated where hand-picking becomes infeasible
  • Log targets need a correction term before converting back — skipping it silently biases predictions down
  • LASSO trades a little bias for a lot less variance, and sets weak coefficients to exactly zero. It gives no valid p-values, so use it for prediction, not inference
  • A holdout set, touched only once, is the honest final check — everything before it is negotiable, this isn’t
