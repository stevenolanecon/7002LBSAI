Model building for prediction

The workshop built the toolbox on six clean predictors and 281 cars. This session: what happens with dozens of candidate variables — and 4,393 real Airbnb listings.

Label engineering

Choosing the target’s functional form

Log or level?

  • When price is the target, its relationship with predictors is often closer to linear once expressed as \(\ln(price)\)
  • Log differences approximate relative (percentage) differences — often more stable across a wide price range
  • Technical bonus: log prices are often closer to normally distributed, which helps a linear regression approximate the average well

Source: Békés & Kézdi (2021), Ch. 14

The correction that’s easy to forget

If the target was modelled in logs, the model predicts \(\widehat{\ln y}\) — not \(\hat y\). Simply exponentiating underestimates the average:

\[\hat y_j = e^{\widehat{\ln y}_j} \times e^{\hat\sigma^2/2}\]

  • \(e^{\widehat{\ln y}}\) alone recovers the median, not the mean
  • The correction term adjusts for the spread of the regression’s residuals — bigger residual variance, bigger correction
  • Skipping it silently biases every prediction downward

On our own data

level_model = smf.ols("price ~ age + agesq", data=df).fit()

log_pred_raw = np.exp(log_model.predict(car))          # median, not mean
corrected = log_pred_raw * np.exp(sigma2 / 2)           # corrected mean

Feature engineering

Building the right-hand side

The checklist

  1. Missing values — random, or systematic? Impute with a flag column, don’t just drop the observation
  2. Categorical values — binary, or a small set of dummies
  3. Text — mine it for useful signal (a “seminar” keyword, say), otherwise leave it
  4. Functional form — polynomials, splines, logs — the same choices as the workshop, applied to many variables at once
  5. Interactions — worth thinking about, expensive to search exhaustively

Source: Békés & Kézdi (2021), Ch. 14

Real data: Airbnb, London

  • 4,393 Hackney-borough listings, March 2017 snapshot
  • Target: nightly price (USD)
  • ~70 predictor candidates: capacity, room and property type, cancellation policy, review scores, and 50 individual amenity dummies (d_tv, d_petsallowed, d_elevatorinbuilding, …)

Source: Békés & Kézdi (2021), airbnb dataset, osf.io/qyca8

Selecting variables automatically

LASSO

We can’t try every model

  • With \(p\) candidate predictors, the number of possible models explodes — this is an NP-hard problem, not just a big one
  • By hand: domain knowledge drives the choice — interpretable, but slow, and impossible with many interactions
  • By algorithm: let the data suggest which variables earn their place

The LASSO idea

LASSO (Least Absolute Shrinkage and Selection Operator) adds a penalty to the usual OLS minimisation:

\[\min_\beta \left\{ \sum_{i=1}^{N}\left(y_i - \beta_0 - \sum_{j=1}^{k}\beta_j x_{ij}\right)^2 + \lambda\sum_{j=1}^{k}|\beta_j| \right\}\]

  • The penalty shrinks coefficients toward zero
  • Coefficients whose inclusion barely improves fit get shrunk all the way to zero — dropped from the model entirely
  • \(\lambda\) controls how aggressive that is; larger \(\lambda\), fewer surviving variables

The cost: bias

  • OLS is unbiased. LASSO isn’t — that’s the trade it makes for lower variance
  • Unlike OLS, there’s no closed-form solution; an algorithm solves for \(\beta\) and \(\lambda\) together
  • \(\lambda\) itself is chosen by cross-validation: try many values, pick the one with the best CV RMSE

Ridge regression is the same idea with a squared penalty (\(\lambda\sum\beta_j^2\)) instead — it shrinks coefficients but never sets them exactly to zero. LASSO is “L1,” Ridge is “L2.”

Post-prediction diagnostics

Holdout sets

One more split before you trust the number

  • Model selection (BIC, cross-validation) already uses the data — repeatedly
  • Best practice: carve off a holdout set right at the start, and don’t touch it until the very end
  • Work set: model building, model selection, training/test folds — all happen here
  • Holdout set: touched exactly once, to get an honest read on how the chosen model will do on genuinely new data

The workflow

  1. Split the original data into a work set and a holdout set
  2. Inside the work set: training/test folds, k-fold CV, model selection
  3. Re-estimate the winning model on the whole work set
  4. Apply it to the holdout set — untouched until now
  5. Evaluate: this is the honest estimate of live-data performance

Summary

  • Prediction with many candidate variables needs the same discipline as prediction with a few — just automated where hand-picking becomes infeasible
  • Log targets need a correction term before converting back — skipping it silently biases predictions down
  • LASSO trades a little bias for a lot less variance, and does variable selection as a side effect
  • A holdout set, touched only once, is the honest final check — everything before it is negotiable, this isn’t
