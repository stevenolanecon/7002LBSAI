Binary outcomes

Every model so far has had a continuous y. What changes when the outcome is just yes or no?

Does smoking pose a health risk?

Business question: among people who are currently healthy, does smoking meaningfully raise the chance their health declines over the next few years — once other differences between smokers and non-smokers are accounted for?

We have real data: 3,112 people aged 50–60, healthy at the start, tracked four years later. stayshealthy is 1 if still healthy, 0 if not.

The naive answer

Naive answer: compare the fraction of smokers who stayed healthy to the fraction of non-smokers who did. Done.

Why it’s not that simple: smokers and non-smokers differ in plenty of other ways — age, exercise, income, education — exactly the confounding problem from Week 6. And the outcome itself is different from anything we’ve modelled so far: it only ever takes the value 0 or 1.

What we need

  • A regression framework built for a 0/1 outcome, not just a workaround bolted onto OLS
  • A way to interpret coefficients when the outcome is a probability, not a quantity
  • A sense of whether the model is actually any good, when it can never predict a 0 or a 1 exactly

Binary outcomes and the latent variable

What’s different about a 0/1 y

  • The expected value of a binary variable is a probability: \(E[y] = P[y=1]\)
  • Frequency and probability become the same idea: 25% of cases having \(y=1\) is the same statement as a 25% chance of the event
  • So “modelling y” here really means modelling a probability

Where does the 0/1 actually come from?

Think about what “staying healthy” really is — it isn’t binary at all. Health is a continuum: some people are robustly healthy, some are fragile but not yet ill, some are already declining.

There’s an unobserved, continuous latent variable — call it \(y^*\) — representing that underlying health trajectory. We don’t observe \(y^*\) directly. We only observe whether it crossed a threshold:

\[y = \begin{cases} 1 & \text{if } y^* > 0 \\ 0 & \text{if } y^* \le 0 \end{cases}\]

Why the latent variable matters

If \(y^*\) is linear in \(x\) plus some random error — \(y^* = \beta_0 + \beta_1 x_1 + \dots + e\) — then:

\[P[y=1|x] = P[y^*>0|x] = P[e > -(\beta_0+\beta_1 x_1+\dots)]\]

This is a probability, so it has to come from the distribution of that error term \(e\) — specifically, its cumulative distribution function.

  • Assume \(e\) is logistic → you get the logit model
  • Assume \(e\) is normal → you get the probit model
  • Ignore this altogether and model \(y\) directly with a straight line → you get the linear probability model

One family: the Generalized Linear Model

Every model this session share the same three-part structure:

  1. A linear predictor: \(\eta = \beta_0 + \beta_1 x_1 + \dots\)
  2. A link function connecting \(\eta\) to \(E[y|x]\)
  3. A distributional assumption for \(y\)

This is the Generalized Linear Model (GLM). Logit and probit aren’t a separate technique from what you already know — and neither, in a moment, will Poisson be.

The family, laid out

Model Link function Distributional assumption
OLS Identity Gaussian (normal errors)
LPM Identity None — plain OLS applied to a 0/1 y
Logit Logistic Binomial
Probit Normal CDF Binomial
Poisson (next session) Log Poisson
Negative binomial (next session) Log Poisson + dispersion

OLS isn’t outside this framework looking in — it’s the special case where the link function does nothing at all.

The linear probability model

LPM — the simplest option

\[y^P = \beta_0 + \beta_1 x_1 + \beta_2 x_2 + \dots\]

  • \(y^P\) denotes \(P[y=1|x_1,x_2,\dots]\)
  • Just OLS, with a binary y — everything from Weeks 4–6 still applies: logs, splines, interactions, robust SEs
  • Heteroskedasticity-robust SEs are essential — LPM residuals are mechanically heteroskedastic

Not just usually — mechanically: y is Bernoulli, so \(Var[y\mid x] = y^P(1-y^P)\). The residual variance is a direct function of the predicted probability itself, which changes with x by construction. There is no version of this model where the residual spread is constant — homoskedasticity isn’t just unlikely here, it’s ruled out by what a binary variable is.

For inference — uncovering patterns of association — this is rarely a big problem. For prediction, it’s a real one: you can’t tell a client their chance of an outcome is 104%.

Logit and probit

Fixing the range problem

Recall the latent-variable story: \(P[y=1|x]\) has to come from a genuine probability distribution’s CDF — which is bounded between 0 and 1 by construction.

  • Logit: assumes \(e\) is logistic → link function is the logistic function \(\Lambda(z) = \dfrac{\exp(z)}{1+\exp(z)}\)
  • Probit: assumes \(e\) is normal → link function is \(\Phi(z)\), the standard normal CDF
  • Both are increasing, S-shaped, and strictly between 0 and 1

Same data, three link functions

  ],

function jStat_norm_cdf(z) {
  return 0.5 * (1 + erf(z / Math.sqrt(2)));
}
function erf(x) {
  const sign = x < 0 ? -1 : 1;
  x = Math.abs(x);
  const a1=0.254829592,a2=-0.284496736,a3=1.421413741,a4=-1.453152027,a5=1.061405429,p=0.3275911;
  const t = 1/(1+p*x);
  const y = 1-((((a5*t+a4)*t+a3)*t+a2)*t+a1)*t*Math.exp(-x*x);
  return sign*y;
}

Why raw coefficients stop working

  • LPM’s slope is constant — a one-unit change in \(x\) shifts \(y^P\) by the same amount everywhere
  • Logit and probit’s slope changes depending on where you are on the S-curve — steepest at \(y^P=0.5\), flattest near 0 or 1
  • Direct consequence: you cannot read raw logit/probit coefficients the way you read an LPM or OLS coefficient

Marginal effects — the fix

The average marginal effect (AME) is the average, across everyone in the data, of how much \(y^P\) changes for a one-unit change in \(x\).

  • Computed via numerical derivatives, not by hand — that’s what the marginaleffects package is for
  • Has the exact same interpretation as an LPM coefficient
import marginaleffects as me

logit_model = smf.logit("stayshealthy ~ smoking + ever_smoked + female + age + eduyears + income10 + bmi + exerc", data=df).fit()
ame = me.avg_slopes(logit_model)

Is the model any good?

Why R² doesn’t quite work here

  • A probability model will never predict exactly 0 or exactly 1 — so it can never “perfectly” fit a 0/1 outcome the way OLS can fit a continuous one
  • \(R^2\) can still be computed, but it no longer carries the same “share of variance explained” meaning
  • We need measures built for probability outcomes

Three purpose-built measures

  • Brier score — mean squared distance between predicted probability and actual outcome. Smaller is better.
  • Pseudo R² (McFadden’s) — ratio of the model’s log-likelihood to an intercept-only model’s. Works for logit/probit, not LPM (no likelihood function there).
  • Log-loss — a negative number; closer to zero is better.

Calibration — a sharper question

Unbiasedness asks: is the model right on average? Calibration asks something stricter: is it right at every predicted probability level?

Take everyone predicted around a 30% chance of staying healthy. If roughly 30% of them actually did, the model is well calibrated there. Do this across the whole range of predictions — that’s a calibration curve.

Back to the question

So, does smoking matter?

  • Smokers are genuinely less likely to stay healthy — roughly 6–7 percentage points, robust across LPM, logit, and probit, and it survives controlling for age, income, education, and exercise
  • The model is reasonably well calibrated — its predicted probabilities can be trusted, not just its average direction
  • LPM, logit, and probit tell essentially the same story here — a reminder that the fancier model isn’t always the one that changes the answer

Summary

  • A binary y is really a probability to be modelled — the latent-variable story explains why link functions exist, not just that they do
  • LPM is OLS with a 0/1 y — simple, but predicted probabilities can fall outside [0,1]
  • Logit and probit fix the range problem, at the cost of needing marginal effects to interpret coefficients
  • Goodness of fit for probability models means Brier score, pseudo-R², log-loss, and calibration — not \(R^2\) alone
